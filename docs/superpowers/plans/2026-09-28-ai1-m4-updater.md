# AI1 M4: Update checks — Plan

**Spec:** `docs/superpowers/specs/2026-09-28-ai1-m4-updater.md`.

## Tasks

1. Add pure types and logic for update records, version comparison, daily check
   scheduling, and result summaries. Cover malformed versions and bad dates.
2. Add a Node service that checks OpenCode and tmux with Homebrew, reads the
   pinned extension versions and queries Open VSX, and checks AI1 Git status
   when a source checkout is available. Isolate each check so one failure does
   not hide other results.
3. Add a Homebrew update action for OpenCode and tmux only. The owner's click is
   the required confirmation. Use
   argument arrays, a timeout, and captured output. Never use a shell.
4. Add an Updates command and Electron main-process scheduler. Check on start
   and every 24 hours. Persist the completed check time in the Electron user
   data folder. Retry failed checks after one hour. Show results and offer
   **Update Tools** when supported tools are old.
5. Add tests for parsing versions, network responses, subprocess arguments,
   update failures, the daily schedule, and confirmation-before-update.
6. Register the extension in the workspace and Electron application. Update
   the README and M4 spec with any changes made during implementation.
7. Run lint, type checks, unit tests, format checks, build, and all hidden e2e
   tests. Commit the updater on its feature branch, then fast-forward `main`.
   Do not push.

## Checks

- Startup does not run an installer.
- The main-process timer does not keep AI1 alive.
- The Homebrew update action names only the OpenCode and tmux formulas.
- No update action changes AI1 source files or app files.
- Never use the owner's real browser cookies or OpenCode service in tests.
